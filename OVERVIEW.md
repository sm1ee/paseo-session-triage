# Session triage

See the Paseo sessions that need your attention in one place. Filter the list by status, open a session, or check the attention count in the desktop and web sidebar. The icon guide is available from the screen toolbar. The sidebar shortcut is hidden in the iOS and Android apps; open Session triage from the Command Center there.

The icons mean:

- 🔴 **Error:** Paseo reports an agent error.
- ❓ **Needs your input:** A permission request is pending, or the agent asks for a decision or reply.
- 📤 **Ready to send:** A draft appears ready for you to review and send.
- 🟠 **Needs review:** The work is unfinished, or the latest update is unclear.
- 👀 **Waiting on a result:** The agent appears to be waiting for CI, a build, a deployment, or a review.
- ⏳ **Working:** The agent is running a turn or starting up.
- ○ **Idle:** No active turn. Recent replies are checked automatically.
- ✅ **Done:** The latest reply says the work is done. Check the result yourself.

Session triage checks Paseo metadata in the background. Idle sessions are classified by a serial reply queue that reads one page of up to 20 recent timeline items, with a three-second gap after each session. Event messages are reused when available. A content-free activity hash and classification enums survive reloads, so unchanged work, renamed titles, and icon edits do not trigger repeat reads. Failed/empty replies need review and are not automatically retried for unchanged activity; Check reply allows a manual recheck. No model calls are used for this classification. Pending permissions and errors come from Paseo. Labels inferred from chat wording can be wrong; ✅ does not verify a build, test, deployment, or submission.

By default, it shows the 20 most recent top-level sessions. Settings let you include subagents and change the limit. The screen and sidebar check for updates while open, and you can refresh the list yourself.

The optional Update title icons setting updates session and workspace markers after lifecycle events. Existing title-update preferences are respected. Changes are queued one at a time, repeated events are merged, and unchanged titles are skipped. When a completed-turn event includes recent messages, the plugin uses those items. Paseo 0.13 sends no message content in this event; the bounded serial reply queue classifies each changed idle session once. Running turns and pending permissions take precedence, and stale results are discarded. Whole conversations are never scanned.

**Name new sessions** queues one initial title when a newly created top-level session starts its first turn, while **Generate titles** is on. It shares the selected model, source, reasoning, serial queue, and daily quota. It bypasses the normal completed-turn interval and title-length threshold. Existing title uses only the initial title (up to 320 characters); Active goal or recent work prefers a verified running Goal, otherwise sends one user message from a single 6-item recent page (up to 600 characters), falling back to the initial title if that message has already left the bounded page. It does not include assistant messages for initial naming. It never scans older pages or existing sessions at startup. The first completion does not trigger another generation; later turns follow the normal interval. Turn the option off to retain completed-turn generation only. New turns and title edits prevent stale initial results from overwriting current work.

**Generate titles** is off by default. Open Settings in the dashboard toolbar, choose an enabled Paseo model, and select a title source. Existing title sends only the title (up to 320 Unicode characters), with an optional 40-character eligibility threshold. Active goal or recent work first uses a verified running Goal from the optional session-recovery integration (up to 600 Unicode characters of its objective). It excludes paused, blocked, limited, completed, stopped, and disconnected goals and never resumes or controls them. If no running goal can be verified, it generates a concrete task name from at most the latest user message and subsequent assistant reply (600 Unicode characters each), reusing event content or fetching one page of up to 6 recent timeline items after reserving the request budget. It excludes reasoning, tool output, and code blocks. It can replace a short generic goal title with a longer task name, up to 40 characters. The selected title provider receives these excerpts only when Active goal or recent work is selected; existing installations keep the title-only source.

In Active goal or recent work, enter any whole number from 1 to 100 in Update every and press Save. Automatic updates run after that many successfully completed turns per top-level session (5 by default). Existing title mode keeps its once-per-session automatic attempt rule. No Goal or conversation reads occur before the interval is due and the request budget is reserved. Counts stay in bounded memory and restart after reloads, settings changes, or archiving; no history scan or per-turn disk write is added. Use Generate session title in the Command Center to explicitly regenerate an idle session's title. Automatic and manual attempts share a daily limit (5 by default), including failed or cancelled attempts. A failed scheduled request waits for a new full interval; the same completion is never retried. There are no fallback models. A manual generation restarts the interval. Goal state is checked again before saving, and stopped or changed goals discard the result. Automatic jobs run one at a time, at most once per minute. Enabling the feature does not scan session history. Choose a small model and the lowest reasoning setting to reduce cost; provider overhead can add tokens beyond the prompt.

**Include idle sessions** is off by default. Enable it to name existing idle top-level sessions without waiting for completed turns. It checks up to 50 metadata entries every 15 minutes after an initial 10-second delay, advancing through older sessions and queuing at most 10 candidates. The same source, one-at-a-time generation, and daily quota apply. A persistent activity hash skips unchanged sessions before reading goals or messages. New messages or changes in provider token-usage metadata allow another attempt; title/icon changes do not. Periodic and manual attempts also record activity. Failed or unclear attempts are skipped until activity changes, while quota-blocked sessions can be considered later. Running turns, pending permissions, errors, archived sessions, subagents, and internal helpers are excluded. No new history scan is added beyond the bounded excerpt read for a due title request.

Title generation requires Paseo 0.12 or later with background workspaces. It reuses one dedicated background workspace with an empty context directory and removes each delegated helper session after its request. Helpers are created as children of their target sessions, and the confirmed parent label keeps them out of Paseo attention pushes. Only helper sessions created by this plugin are removed. It never sends title prompts to, approves permissions for, stops, deletes, archives, or resumes existing sessions or goals. Status icons, folder prefixes, and names edited while generation is running are preserved. A new turn cancels conversation-based generation; a verified unchanged running Goal can keep its title job across native turns without interrupting the session.

Excerpts stay in plugin memory and are not written to plugin files or logs. Settings are stored by Paseo; content-free attempt records survive reloads. Paseo's built-in workspace naming is separate, under Settings → Host → Metadata. Other triage features require stable Paseo 0.11.4 or later.
